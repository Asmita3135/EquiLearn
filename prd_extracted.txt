1. Product Overview
EquiLearn is a multimodal accessibility intelligence system that takes educational content in different formats and
transforms it into representations suitable for users with different accessibility needs.

6. Stage-by-Stage Product Workflow
STAGE 1 — INPUT ACQUISITION
Input: PDF, image, audio, video, or text.
Processing: Determine content type and extract raw components. This stage is basic file/format processing, not AI.
Output: Raw bytes, decoded streams, text content, images, audio, video.
STAGE 2 — DATA PREPARATION
Images: resize, denoise, deskew, normalize.
Audio: resample to 16 kHz mono, trim silence, normalize amplitude.
Video: extract audio track and keyframes where required.
Text: normalize Unicode, fix encoding, split into paragraphs.
STAGE 3 — MODALITY ROUTING
Digital PDF with usable text → direct text extraction.
Scanned page/image → OCR.
Speech → ASR/Whisper.
Visual content → VLM.
Text → NLP + LLM.
STAGE 4 — AI/ML PROCESSING
PaddleOCR for OCR; Tesseract as fallback; Qwen2.5-VL / GPT-4o-type VLM for visual understanding; Whisper
large-v3 for speech recognition; GPT-4o / Gemini Flash / Llama for summarization and simplification; Web Speech API
/ gTTS for text-to-speech.
STAGE 5 — INFORMATION UNDERSTANDING
Text: readability, sentence length, lexical density, passive voice, complexity, key terms.
Images: objects, actions, spatial relationships, visual descriptions.
Audio: transcript segments, timestamps, speaker changes, topic shifts.
STAGE 6 — TRANSFORMATION
Text → summarization, simplification, key-term extraction.
Images → alt-text.
Audio/video → transcript, timestamped captions, VTT.
Text → speech-ready representation.
STAGE 7 — ACCESSIBILITY INTELLIGENCE
A rule-based decision layer selects the appropriate representation for the accessibility profile.

STAGE 8 — FINAL ACCESSIBILITY PACKAGE
All processed information is combined into a structured package containing raw text, alt-text, transcript, summary,

7. Member-by-Member Workflow
MEMBER 1 — Vision & Document AI
Primary responsibility: Documents + Images + OCR + Visual Understanding
M1-STAGE 1 — Document Processing
Understand PDF types, implement digital-text extraction, identify when OCR is required, handle scanned pages, and
convert pages into images when needed.
M1-STAGE 2 — Image Preprocessing
Resize, denoise, deskew, normalize, and prepare images for OCR/VLM processing.
M1-STAGE 3 — OCR
Primary: PaddleOCR. Fallback: Tesseract.
Pipeline: Image → text detection → text recognition → bounding boxes → confidence.
Output: Text, bounding boxes, confidence scores.
M1-STAGE 4 — Vision-Language Model
Use Qwen2.5-VL-3B-Instruct or an equivalent approved VLM to understand objects, scenes, diagrams, spatial
relationships, and visual content. OCR tells what text is written; VLM helps explain what the whole visual means.
M1-STAGE 5 — Alt-Text
Image → VLM → description → alt-text. For complex diagrams, combine OCR labels with VLM visual relationships to
form a structured description.
M1-STAGE 6 — Blind User Support
PDF → text + images → OCR + VLM → text labels + visual description → Member 3 language processing → unified
description.
M1-STAGE 7 — Low-Vision Support
Provide OCR text, image descriptions, visual information, and important visual content. Presentation enhancement
itself is outside this core AI PRD.
M1-STAGE 8 — Evaluation
OCR: CER, confidence, recognition failures. VLM: human description rating, plus BLEU/ROUGE where appropriate,
and hallucination cases.

MEMBER 2 — Audio & Speech AI
Primary responsibility: Audio + Video Audio + Speech Recognition + Transcription + Caption Generation + TTS
investigation
M2-STAGE 1 — Audio Extraction
For video: Video → FFmpeg → audio track. Then audio → 16 kHz → mono → silence trimming → Whisper-ready
audio.
M2-STAGE 2 — Automatic Speech Recognition
Model: Whisper large-v3 / large-v3-turbo.
Pipeline: audio → mel-spectrogram → transformer encoder/decoder → text tokens → timestamps.
Output: transcript, segments, start/end timestamps, language.
M2-STAGE 3 — Deaf/Hard-of-Hearing Workflow
Lecture video → extract audio → preprocess → Whisper → speech-to-text → timestamped segments → VTT
formatting → captions + transcript.
M2-STAGE 4 — Transcript Processing
Handle timestamp generation, segment creation, transcript formatting, speaker-change approximation, and technical
terminology preservation.
M2-STAGE 5 — VTT Generation
Convert transcript + timestamps into WebVTT captions.
M2-STAGE 6 — TTS
Investigate Web Speech API and gTTS. Text → TTS → speech. TTS supports blind users, can be optional for
low-vision users, and can assist dyslexia workflows.
M2-STAGE 7 — Audio Evaluation
Evaluate WER, timestamp accuracy, noisy audio, accented speech, incorrect transcription, and hallucinated speech.

MEMBER 3 — NLP & Accessibility Intelligence
Primary responsibility: Text Understanding + LLM + Simplification + Summarization + Dyslexia + Accessibility
Decision Logic
M3-STAGE 1 — Text Processing
Process text from digital PDFs, OCR, visual descriptions, and transcripts. Perform paragraph/sentence segmentation,
Unicode normalization, and complexity analysis.
M3-STAGE 2 — Readability Analysis
Calculate Flesch Reading Ease, Flesch-Kincaid Grade Level, average sentence length, lexical density, and
word-frequency bands.
M3-STAGE 3 — Complexity Detection
Determine whether content is difficult, identify difficult sentences/words, and identify information that must remain
unchanged.
M3-STAGE 4 — LLM Summarization
Use an approved LLM such as GPT-4o, Gemini Flash, or Llama for important-information identification and condensed
representations.
M3-STAGE 5 — Dyslexia Simplification
Original text → complexity analysis → LLM → simplification → readability check. If readability is insufficient, refine the
prompt and run again, with a maximum of two refinement iterations.
M3-STAGE 6 — What the LLM Changes
Syntactic simplification, lexical simplification, passive-to-active conversion where appropriate, and clearer coreference.
The requirement is to reduce linguistic complexity without losing important meaning.
M3-STAGE 7 — Blind User Language Processing
Combine OCR text + VLM visual description + context → LLM → unified meaningful description.
M3-STAGE 8 — Accessibility Decision Logic
User profile → deterministic decision table → required representation. This is rule-based, not ML.
M3-STAGE 9 — Final Content Transformation
Combine outputs into summary, simplified text, key terms, complexity score, unified visual descriptions, TTS-ready
sentences, and simplified transcripts as required.
M3-STAGE 10 — NLP/LLM Evaluation
Summarization: ROUGE-L/BERTScore. Simplification: Flesch Reading Ease/FKGL/SARI. Human evaluation:
semantic preservation, readability, hallucination.

Central principle: EquiLearn is not training one giant AI model. It combines pretrained multimodal models through a
structured routing and transformation pipeline. The core intelligence is in how OCR, VLM, ASR, NLP/LLM, TTS, and
deterministic accessibility rules work together.
